# 地图数据可视化编辑器 · 开发文档

> 状态：**需求已确认（2026-10-31）**，待实现
> 产物：`tools/map-editor.html`（单文件静态网页）

## 1. 背景与目标

主应用（深圳中学室内导航）的路网与 POI 数据存在若干已知缺口（J 栋入口为补丁边、室外无路网、跨层边靠推断等，见 `docs/DATA.md` §7）。目前修改 `data/map-data.json` 只能手改 JSON，缺乏可视化手段。

本工具提供一个**离线可视化编辑器**，用于在浏览器中直接查看、编辑、修复地图数据，并导出为与主应用兼容的 `map-data.json`。

### 1.1 目标

- 在楼层平面图上可视化查看 / 编辑地图数据的全部四类实体：路网节点与边、POI、房间多边形、楼层元数据；
- 支持导入、导出 `map-data.json`（与 `data/map-data.json` 同构）；
- 提供撤销/重做与数据校验报告，保证编辑安全。

### 1.2 非目标（明确不做）

- ❌ 不接入 onemap.top 接口、不重新抓取数据（抓取属 `data/build_data.py`）；
- ❌ 不修改构建管线（`scripts/build.py`）、不直接产出 `index.html` / `map-data.js`；
- ❌ 不做自动保存草稿（localStorage 暂存）——按需求确认排除；
- ❌ 不做多人协作、不做后端服务。

## 2. 需求确认记录

| 项 | 确认结果 |
|---|---|
| 编辑范围 | **全量**：路网节点与边、POI/房间属性、房间多边形与轮廓、楼层元数据 |
| 导出方式 | **仅导出 `map-data.json`**（浏览器下载），由用户手动放回 `data/` 并自行运行构建 |
| 技术形态 | **纯单文件 HTML + 原生 JS**，零外部依赖，双击即用，离线可用 |
| 辅助功能 | **撤销/重做** + **数据校验报告**；不要自动保存草稿 |

### 2.1 二轮设计决策（2026-10-31 确认，全部按推荐）

| 决策点 | 结论 |
|---|---|
| Q1 关联实体联动 | **默认联动**：一个"房间"的 4 份影子数据（节点 / 标签 / POI / 同名房间多边形）在导入时按 xy/name 建立映射；拖动、改名节点时联动更新其标签、POI 与同名多边形。校验器兜底报告失联实体 |
| Q2 派生字段自动维护 | 移动节点时**自动重算**关联 **kind-0** 边权重（欧氏距离/unitPerMeter，拖拽结束时一次性算）；kind-1/2/3 权重不自动动。**裁定（code-review 2026-10-31）**：派生权重按源数据惯例保留 2 位小数（源数据 4472/5000 为 2 位），此为派生值取整而非导出取整，不违反 Q5；手动覆盖的权重在该节点下次移动前保持有效，移动即视为重新派生。多边形几何编辑后自动重算楼层 `bounds`（= 多边形 bbox ± 40，实测全楼层成立） |
| Q3 搜索定位 | **加搜索框**：按名称模糊匹配 POI/节点/标签，点击结果平移居中并选中（P2 阶段标配） |
| Q4 批量操作边界 | v1 多选仅支持**批量移动 + 批量删除**；批量属性编辑留待后续版本 |
| Q5 导出保真度 | **接受语义等价往返**：indent=4 + 键序保持（meta→floors→nodes→edges→pois），数值不丢精度；`4045.0`→`4045` 的 JSON 浮点写法差异可接受。验收标准 7 相应从"逐字节等价"放宽为"语义等价" |

## 4. 数据格式规格

工具的导入/导出文件即 `data/map-data.json`，schema 如下（已实测校准）。

```jsonc
{
  "meta": {
    "name": "深圳中学",
    "source": "https://www.onemap.top/szzxtest/",
    "unitPerMeter": 10.0,          // 1 单位 ≈ 0.1 m
    "floorOrder": ["L15", ...],    // 楼层显示顺序（自上而下），含全部楼层 id
    "mainComponent": "667106"
  },
  "floors": [
    {
      "id": "L1",                  // 楼层唯一 id
      "name": "L1",
      "note": "",
      "level": 0,                  // 垂直层级（ground=0, B1=-1, GF1=0.5 …）
      "kind": "indoor",            // indoor | outdoor
      "bounds": [x0, y0, x1, y1],
      "polys": [                   // 平面多边形
        { "t": "room",             // 见 4.1 类型表
          "p": [x1,y1,x2,y2,...],  // 扁平坐标数组（闭合不重复首点）
          "n": "D202" }            // 名称，部分类型没有该字段
      ],
      "labels": [
        { "n": "D202", "x": 4045, "y": 4158.8,
          "c": "workstationaction" }  // 见 4.2 类别表
      ]
    }
  ],
  "nodes": [
    [x, y, floorIdx, code, name, building]
    // floorIdx 为 floors 数组下标（0-based）
    // code 如 "stair" / "lifts" / "workstationaction" / "roadmark" / "" 等 20 种
  ],
  "edges": [
    [a, b, weight, kind]
    // a,b 为 nodes 数组下标；weight 为距离（米）
    // kind: 0=walk(6329) 1=stair(202) 2=lift(151) 3=entry(15)
  ],
  "pois": [
    { "id": "664025", "n": "DT-1", "f": "B1",
      "x": 2723.4, "y": 5242.2,
      "t": "电梯", "b": "行政楼",
      "i": 405 }                   // 关联的 nodes 下标
  ]
}
```

### 4.1 多边形类型（`polys[].t`）

| t | 数量 | 含义 | t | 数量 | 含义 |
|---|---|---|---|---|---|
| `room` | 1350 | 房间 | `dash` | 263 | 虚线区域 |
| `stair` | 259 | 楼梯 | `mech` | 197 | 机房 |
| `wc` | 579 | 卫生间 | `lift` | 170 | 电梯井 |
| `atrium` | 132 | 中庭 | `indoor` | 98 | 室内通用 |
| `outline` | 82 | 楼层轮廓 | `roadlabel` | 24 | 路名标注区 |
| `road` | 16 | 道路 | `other` | 13 | 其他 |
| `grass` | 32 | 草地 | `water` | 2 | 水体 |

### 4.2 标签类别（`labels[].c`）

`workstationaction`(1344) / `stair`(258) / `lifts`(170) / `roadmark`(24) / `gate`(2)

### 4.3 节点 code 枚举（`nodes[][3]`）

`workstationaction`(1350)、`stair`(259)、`toilets`(491)、`lifts`(170)、`machine room`(197)、`xuxian`(263)、`outline`(77)、`Stalls`(125)、`ground`(106)、`male/female toilets`(44+44)、`roadmark`(24)、`caopi`(29)、`road`(12)、`ELEVATION`(5)、`road profile`(4)、`caodi`(3)、`Garden`(2)、`gate`(2)、`Your location`(1)、`""`(3489)

### 4.4 POI 类型（`pois[].t`）

`教室 / 功能室`(1344)、`楼梯`(258)、`电梯`(170)、`卫生间`(3)、`男卫生间`(40)、`女卫生间`(41)、`室外地点`(18)

### 4.5 引用完整性约束

编辑器必须维护以下不变量（也是校验规则的基础）：

1. `nodes[][2]`（floorIdx）必须是合法 `floors` 下标；
2. `edges[][0..1]` 必须是合法 `nodes` 下标，且 `a ≠ b`；
3. `pois[].i` 必须是合法 `nodes` 下标；`pois[].f` 应等于该节点所在楼层的 `id`；
4. `meta.floorOrder` 应包含全部 `floors[].id` 且无重复；
5. `edges[][2]`（weight）> 0；kind ∈ {0,1,2,3}；
6. 删除楼层 / 节点时，必须级联处理或阻止删除（见 §6.5）。

## 5. 总体设计

### 5.1 文件结构

```
tools/
├─ DEV.md              # 本文档
└─ map-editor.html     # 编辑器（单文件，HTML+CSS+JS 全内联）
```

### 5.2 模块划分（单文件内部分区）

| 区块 | 职责 |
|---|---|
| 数据层 | 解析 / 序列化 map-data.json；持有编辑中的内存数据模型 |
| 历史栈 | 命令模式（command stack）实现撤销/重做 |
| 渲染层 | Canvas 2D：多边形、标签、节点、边、选中态、辅助线；平移缩放变换 |
| 交互层 | 工具模式（选择/新增节点/连线/…）、鼠标拾取、拖拽、属性面板 |
| 校验器 | 不变量检查 + 启发式问题扫描，产出校验报告 |
| UI 壳 | 工具栏、楼层切换栏、图层面板、属性面板、报告抽屉 |

### 5.3 渲染方案

- **Canvas 2D**（单 canvas 或双层 canvas），坐标变换：`screen = (world - view.offset) * view.scale`；
- 平移（拖拽 / 滚轮）+ 缩放（滚轮 / 按钮，锚点为鼠标位置）；
- **视口裁剪**：仅绘制 `bounds` 与视口相交的多边形/节点；
- 图层开关：多边形 / 标签 / 节点 / 边 / POI / 网格，各自可隐藏；
- 多边形填色按 `t` 类型区分（参考主应用 `src/js/10-floorplan.js` 配色），便于识别；
- 节点 / 边按 `code` / `kind` 区分颜色（walk/stair/lift/entry），选中实体高亮描边。

## 6. 功能需求

### 6.1 导入

- 工具栏「导入」按钮 + 页面拖拽导入；
- 解析 JSON 后做结构预检（schema 必备字段、数组长度一致性），失败给出明确错误信息，不进入编辑态；
- 导入成功后定位到 `floorOrder` 的默认楼层（L1），全图适配视口；
- 已有未导出编辑时导入新文件，弹确认提示（覆盖当前编辑）。

### 6.2 视图与导航

- 楼层切换栏（19 层，按 `floorOrder` 排列），点击切换当前编辑楼层；
- 仅当前楼层的数据可编辑，其余楼层可按需以半透明参考显示（可开关）；
- 平移 / 缩放 / 适配全图 / 回到原点；
- 鼠标悬停显示实体摘要（类型 + 名称 + 坐标）。

### 6.3 选择与属性编辑

- 单选：点击拾取（节点 > 边 > POI > 多边形，按优先级命中）；框选：拖拽多选节点；
- 属性面板显示并可编辑选中实体的全部字段：
  - **节点**：x、y、floorIdx（楼层下拉）、code、name、building；
  - **边**：a、b（只读显示端点坐标）、weight、kind（下拉：walk/stair/lift/entry）；
  - **POI**：n、f、x、y、t、b、i（关联节点）；
  - **多边形**：t（下拉）、n；
  - **楼层**：id、name、note、level、kind；
- 数值输入实时回显画布；`id`、`code`、`t` 等枚举字段用下拉限制非法值（允许手动输入新值以兼容未来扩展，但校验器会提示）。

### 6.4 几何编辑

| 操作 | 交互 |
|---|---|
| 移动节点 / POI / 标签 | 选中后拖拽（可选吸附到网格，网格间距可配，默认 10 单位 = 1 m）。**节点移动时联动**其标签/POI 位移，并自动重算关联 kind-0 边权重（§2.1 Q2） |
| 移动多边形 | 选中后整体拖拽 |
| 编辑多边形顶点 | 进入顶点编辑模式：拖拽顶点、在边上点击插入顶点、Del 删除顶点（≥3 点） |
| 新增节点 | 「新增节点」工具：画布点击落点，弹出属性面板填 code/name |
| 新增边 | 「连线」工具：依次点击两个节点生成边，弹出设 kind/weight（默认按欧氏距离 ×0.1 m 自动算 weight） |
| 新增 POI | 「新增 POI」工具：点击落点 + 关联最近节点（可改） |
| 新增多边形 | 「绘制多边形」工具：逐点点击，双击/Enter 闭合，选 t 类型 |
| 新增标签 | 选中多边形或节点后「添加标签」，或独立标签工具点击落点 |
| 删除 | 选中后 Del / 工具栏删除按钮，带确认（涉及级联时提示受影响实体数量）；多选批量删除按 §2.1 Q4 仅限移动与删除 |

### 6.5 删除级联规则

| 删除对象 | 级联行为 |
|---|---|
| 节点 | 阻止删除仍被边引用的节点，除非勾选「同时删除关联边」；同步提示关联 POI 数量 |
| 边 | 直接删除，无级联 |
| POI / 标签 / 多边形 | 直接删除，无级联 |
| 楼层 | 阻止删除仍有节点/多边形的楼层，除非勾选「级联删除楼层内全部数据」；自动从 `floorOrder` 移除并修正所有 `floorIdx` |

### 6.6 楼层元数据编辑

- 属性面板编辑 `meta`（name、unitPerMeter、source）与楼层字段；
- 支持新增楼层（生成空 polys/labels）、删除楼层（按 6.5 级联）；
- `floorOrder` 通过楼层栏的上移/下拖调整，`meta.floorOrder` 同步更新。

### 6.7 撤销 / 重做

- 命令模式：每个编辑操作（含拖拽结束后的合并位移）记录 before/after 快照或反向命令；
- 快捷键 `Ctrl+Z` / `Ctrl+Y`（`Ctrl+Shift+Z` 亦可）；工具栏按钮显示可用状态；
- 历史栈深度 ≥ 100 步；导入新文件清空历史。

### 6.8 数据校验报告

「校验」按钮运行检查并输出报告抽屉，逐条列出 **错误（阻断导出建议）/ 警告 / 提示**：

**错误级（违反 §4.5 不变量）：**
- floorIdx / 边端点 / POI 关联节点越界；
- 自环边（a=b）、weight ≤ 0、非法 kind；
- `floorOrder` 缺失或重复楼层 id；楼层 id 重复。

**警告级（启发式）：**
- 孤立节点（度为 0 且非室外 ground 层）；
- 悬空 POI（关联节点不在主连通分量）；
- `pois[].f` 与节点实际楼层不一致；
- 跨层边（两端 floorIdx 不同）但 kind=0（walk）——疑似漏标 stair/lift；
- **同层**重复边（同一对节点多条边）；
- **同层**零长边（两端坐标重合；跨层楼梯/电梯节点同坐标是正常形态，不告警——code-review 裁定）；
- **失联影子实体**（§2.1 Q1）：节点与标签/POI/同名多边形的 xy/name 映射断裂，或 POI 与关联节点坐标漂移 > 1 单位；
- 未知枚举值（code/t/c 不在已知集合）——允许扩展但提示。

报告支持点击条目**定位到画布对应实体**并选中。

### 6.9 导出

- 「导出」按钮生成 `map-data.json` 下载（文件名默认 `map-data.json`，可改）；
- 导出前自动运行校验：存在**错误级**问题时弹窗列出并允许「仍要导出」/「取消」；
- 导出内容与导入结构完全同构：字段顺序尽量保持稳定（meta → floors → nodes → edges → pois），数值不丢精度（保留原始精度，不做无谓取整）；
- 导出不包含任何编辑器私有字段。

## 8. 工作流（与主应用衔接）

```
1. 双击 tools/map-editor.html 打开编辑器
2. 导入 data/map-data.json
3. 可视化编辑（撤销/重做随时可用）
4. 「校验」查看报告，修复错误级问题
5. 「导出」下载 map-data.json
6. 用导出文件覆盖 data/map-data.json        ← 手动
7. python scripts/build.py                  ← 手动，重建 map-data.js 与 index.html
```

⚠️ **注意**：`data/build_data.py` 重新抓取会**整体覆盖** `map-data.json`，手工修改将丢失。修改应在抓取产物之上进行，或改完后不要再运行 `build_data.py`。

## 9. 验收标准

1. 双击 HTML 可离线打开，无任何网络请求、无外部依赖报错；
2. 可导入当前 `data/map-data.json`（5.4 MB）并在 3 s 内完成首屏渲染，19 层可切换；
3. 四类实体均可查看与编辑（含多边形顶点编辑），编辑结果在画布实时可见；
4. 撤销/重做覆盖所有编辑操作，≥100 步；
5. 校验报告能检出人为构造的越界引用、自环边、孤立节点等样本问题，且可点击定位；
6. 导出的 JSON 可被主应用构建脚本接受（`python scripts/build.py` 成功），且导航功能正常（改名 / 调边后路线结果符合预期）；
7. 空手编辑一轮（移动节点→撤销→重做→导出）数据**语义等价**往返（未编辑部分结构、数值、键序一致；`x.0`→`x` 浮点写法差异可接受，见 §2.1 Q5）。
