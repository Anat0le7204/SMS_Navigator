# 数据说明

## 1. 来源

深圳中学室内地图站点：`https://www.onemap.top/szzxtest/`

底层为 cloudindoormap SDK，项目参数：

| 参数 | 值 |
|---|---|
| projectID (`pid`) | `114` |
| buildingID | `117` |
| accessToken | `BAF3CB32-E8F2-40A6-AE1A-A5BFE2CB6E14` |
| 楼层 SVG | `viewBox="0 0 8000 8000"`，与点位坐标一致 |

使用到的公开接口：

| 接口 | 用途 | 体积 |
|---|---|---|
| `/ids/map/getAreaInfoMulPro?pids=[114]&lan=SC` | 楼层、区域元数据 | ~3.4 MB |
| `/ids/map/getPointMulPro?pids=[114]&lan=SC` | POI + 路网节点/边 | ~845 KB |
| `/ids/map/getAreaInfo?pid=114&lan=SC&buildingID=117&floorID=...` | 单层房间多边形 | 每层 100–300 KB |
| `/ids/map/GetMapBuildingInfo?pid=114` | 楼层清单 | ~184 KB |

`data/build_data.py` 会缓存原始响应并在缺失时重新下载。

## 2. 楼层

共 19 个“楼层”，注意它不是单栋楼，而是**全校区按标高划分的层**：

| id | 含义 | 垂直层级 |
|---|---|---|
| `ground` | 室外地面、道路、田径场 | 0 |
| `B1` | 地下车库 | -1 |
| `L1` | 校园地面层（全校区连接层） | 0 |
| `GF1` | 文体楼夹层 | 0.5 |
| `L2` | 二层 | 1 |
| `GF2` | 文体楼夹层 | 1.5 |
| `L3`–`L15` | 三至十五层 | 2–14 |

- A–D 区为教学楼，I–L 区为宿舍 I/J/K/L 栋；
- `L1` 的 318 个节点连成一体，可从教学楼走到宿舍、文体楼；
- `L2` 及以上按楼栋分裂为多个连通分量。

## 3. 坐标与比例

- 地图单位为 8000×8000 的平面坐标，与官方楼层 SVG 同源；
- SDK `pixelPerMeter = 10`，因此 **1 单位 ≈ 0.1 m**；
- 实测校验：北环大道 ↔ 泥岗西路约 4480 单位 ≈ 450 m；教学楼 L2 轮廓约 216×247 m，与卫星图吻合。

## 4. 路网

`getPointMulPro` 返回的 `Point.Path` 即为路网边：

- 6,697 个节点，6,329 条同层无向边；
- 节点类型：房间（`workstationaction`，叶子节点）、楼梯（`stair`）、直梯（`lifts`）、卫生间、机房、门（`gate`）、室外路名（`roadmark`）；
- 房间节点通过 `Path` 挂在走廊节点上，天然可作为起终点。

### 4.1 跨层连接（推断）

原始数据**没有跨层边**。构建时按以下规则补全：

1. 同名楼梯 / 电梯；
2. 相邻楼层；
3. 两节点坐标距离 < 12 m（同层坐标去重后取中位点）；
4. 每层垂直代价：楼梯 9 m、电梯 6 m（`3 × level diff`）。

共补出 353 条垂直边。

### 4.2 室外接入

室外 `ground` 层的 395 个点**没有任何边**。做法：

- 取 L1 内部最大连通分量（318 节点）作为校园地面步行主网络；
- 将室外命名 POI（校门、楼栋名）就近接入该网络，距离 ≤ 50 m，权重 = 距离 + 2 m；
- 共 14 条合成边。

### 4.3 可达性补丁

J 栋（宿舍 J）在 L1 没有建模入口，其楼梯只从 B1/L2 起。若不处理，J 栋 198 个房间不可达。构建时补一条：

`L1 主网络 → L2 LT13 楼梯`（约 27 m，类型 `entry`）。

补丁后主连通分量 5,852 / 6,697 节点，1,874 个命名 POI 中仅 9 个室外路名不可达（已从搜索索引排除）。

## 5. 房间与标签

- 1,350 个 `workstationaction` 房间，命名以编号为主（`D202`、`I1501`、`J0308`）；
- 少量功能室有中文名（`形体室`、`拳道`、`器材室`、`淋浴`）；
- 房间标签取节点坐标，比多边形质心更贴近门/走廊一侧；
- 标签在渲染时做屏幕空间碰撞避让，缩放越小显示越少。

## 6. 生成物格式

`data/map-data.json`：

```jsonc
{
  "meta": { "name": "深圳中学", "unitPerMeter": 10, "floorOrder": ["L15", ...] },
  "floors": [
    { "id": "L1", "name": "L1", "level": 0, "kind": "indoor",
      "bounds": [x0,y0,x1,y1],
      "polys": [{ "t": "room", "p": [x1,y1,...], "n": "D202" }],
      "labels": [{ "n": "D202", "x": 4045, "y": 4158.8, "c": "workstationaction" }] }
  ],
  "nodes": [[x, y, floorIdx, code, name, building], ...],
  "edges": [[a, b, weight, kind], ...],   // kind: 0 walk 1 stair 2 lift 3 entry
  "pois": [{ "i": 840, "n": "D202", "f": "L2", "x": ..., "y": ..., "t": "教室 / 功能室", "b": "教学楼" }]
}
```

`data/map-data.js` 是开发用的 `window.MAP_DATA = {...}` 包装，由 `scripts/build.py` 生成。

## 7. 已知数据缺口

- 楼层高度字段为空，跨层距离只能按当量折算；
- 室外没有路网，校门→L1 为合成连接，不支持在室外道路任意点选；
- J 栋入口为补丁，非官方边；
- 部分楼栋（如文体楼夹层）的楼梯与 L1 的对应关系依赖同名 + 坐标匹配，可能与真实通行规则略有差异；
- 班级名称、无障碍信息、电梯运行时间不在数据中。
